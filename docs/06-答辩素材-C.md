## 二、四条链路，一张嘴讲清

**① 文字记账**
```
输入"午饭 25" → 解析（B 的 parse_record，没接通时用页面内置规则）
→ 统一成 9 字段 record → 确认卡片（金额/类别/时间/商户可改）
→ 调 A 的 add_transaction（元转分入库）→ 返回编号 #1 → 清空输入框
```

**② 小票记账**
```
上传图片 → 入口校验（大小/格式/文件头/是否损坏）
→ 调视觉模型（glm-4v-plus）→ JSON → 洗成同一套 9 字段
→ 实付金额规则兜底 → 同一张确认卡片 → add_transaction(source=receipt)
```

**③ 账单列表**
```
选时间范围/类别/收支 → A 的 list_transactions → 按天分组 → 每天小计 → 表格
```

**④ 自检**
```
python scripts/check_e2e.py   # 临时库跑完整链路，退出码 0 才算通
```

## 三、为什么这么写（答辩最值钱的部分）

### 1. 确认卡片，不是"识别完直接入库"

AI 会错，而且**错的时候往往很自信**。实测：外卖截图取错金额那次，`confidence` 0.9；
便利店小票类别判成"购物"，`confidence` 还是 1.0。

所以设计成：**AI 只负责填，人负责定。** 卡片上四项都可以改，用户点的确认才是入库动作。

### 2. 置信度是门限，不是保证

- `confidence < 0.6` 或 `missing_fields` 非空 → 卡片顶部红色警告 + 必须勾选"我已逐项核对"才能点确认
- `confidence >= 0.6` 且字段齐 → 不额外加坎，但卡片仍然可改

一句话：**"置信度只用来决定拦不拦，不用来保证对不对。"**

### 3. 模型负责读，规则负责校正

外卖单上同时有"总价 15.9"和"实付 13.40"，模型两次都取了 15.9——改 prompt 也没用。
最后用规则兜底：从模型返回的原文里正则找"实付/支付金额/实收"，找到就覆盖金额，并写备注。

为什么这条路对：**金额是纯数字，正则比模型可靠**（和 `money.py` 用 `Decimal` 而不是浮点是同一个思路）。

### 4. 不用 `st.dataframe`，手写 Markdown 表格

`st.dataframe` 内部要 import pandas，而这台机器的 numpy DLL 被系统"应用控制策略"拦了，
pandas 一 import 就 `ImportError`，整页崩。所以账单页的表格是手写 Markdown——零依赖，够演示。

### 5. 兜底双通道，谁没写完都能演示

B 的 `parse_record`、A 的 `add_transaction` 没接通时，页面自动走内置规则 / 会话暂存，
底部状态行**如实显示**当前走的哪条路；对方一实现，页面一行不改就切真函数。

## 四、OCR 错误矩阵（背下来，评委爱挑这里）

| 输入 | 用户看到 | 调模型了吗 |
|---|---|---|
| 空文件 | 没收到图片内容，请重新上传 | 否 |
| 超过 5MB | 图片超过 5MB，请压缩后再上传 | 否 |
| `.gif`/`.pdf` 改名成 `.jpg` | 这个文件不是图片（或扩展名被改过） | 否 |
| 文件头对但内容截断 | 这张图打不开（可能损坏或没传完整） | 否 |
| 风景照/自拍 | 没看出这是账单：请上传小票或支付截图 | 是 |
| 金额看不清 | 不报错，`amount=None` + 追问，必须人工补 | 是 |
| 没配 Key / 占位符 | 视觉模型的 Key 还没填好……（不崩） | 否 |
| 网络/401/超时 | 视觉模型调用失败（写明原因） | 是 |
| 模型返回非 JSON | 视觉模型返回的不是 JSON，没法解析 | 是 |

设计意图一句话：**能不花模型调用钱的错误，就在本地拦住；必须让模型判断的（是不是小票），才发出去。**

## 七、必答 10 问

**1. 用户点一次记账，中间发生了什么？**
输入 → 解析成 9 字段 → 渲染确认卡片 → 用户改 → 组装 record（金额是元）→ `add_transaction` 内部 `to_cents` 转分入库 → 返回 id → 提示编号。

**2. 为什么不让 AI 直接入库？**
模型会错（实测置信度 1.0 也判错类别），且金额错误用户看不见。确认卡片是"人工复核"环节，代价是一次点击，收益是账本可信。

**3. 置信度怎么用？**
当门限：<0.6 或字段不全 → 必须勾选"已核对"；≥0.6 → 不加坎但仍可改。不用它保证正确性。

**4. 小票上有总价和实付，取哪个？**
取实付（用户真正花掉的钱）。prompt 里写了优先级，但模型不稳，所以加 `raw_text` 正则兜底。

**5. 为什么不用 Tesseract？**
中文小票版式乱、字体杂、有手写；传统 OCR 要自己写灰度/去噪/二值化，零基础至少 3 天，抽字段仍不准。视觉模型一次调用出结构化 JSON。

**6. 一张图多少钱、多少秒？**
实测 4-7 秒/张；按官方价目表一张几分钱。答辩时用控制台的真实 token 数换算，不要背数字。

**7. 用户传了假图/坏图怎么办？**
入口看文件头判断真实类型，再用 Pillow 验完整性；不对就在本地拦住，不花模型调用钱。

**8. 账单页为什么不用表格控件？**
`st.dataframe` 依赖 pandas，本机 numpy DLL 被系统策略拦掉，一 import 就崩；改手写 Markdown 表，零依赖。

**9. 你和 B/A 的边界在哪？**
B 返回 9 个字段的 record（金额单位元），A 的 `add_transaction` 负责校验和入库；我只做页面和图片解析，不碰数据层。契约写在 docstring 里，改之前群里说。

**10. 已知问题？**
B 的 `parse_record` 未接入（走内置规则兜底）；类别偶有误判（便利店→购物）；置信度不可作为正确性保证；本机 pandas 不可用。

## 八、30 秒现场演示脚本

1. 打开记账页，点示例按钮「午饭 25，和同事 AA」→ **解析**
2. 把金额改成 `30`，商户填「沙县小吃」→ **确认记账**
3. 指着顶部："已记上 30.00 元 · 餐饮 · 编号 #N"——**编号来自数据库，不是写死的**
4. 切到 **账单** 标签："刚那一笔在这里，按天分组、当天小计"
5. 回到记账页，展开 **📷 拍小票** → 选 `samples/receipts/real_01.jpg` → **识别**
6. 指着卡片："金额是实付 13.40，不是总价 15.90，下方可以展开看识别原文"
7. 勾选「我已逐项核对」（如果置信度低）→ **确认记账**
