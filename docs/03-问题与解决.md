## 已经踩过的坑（骨架阶段）

### 问题 1：pip 装依赖时长时间无响应，看起来像死机

- **现象**：`pip install -r requirements.txt` 卡在 `Downloading altair-6.3.0...` 之后不动，等了十几分钟没有任何输出
- **原因**：`altair 6.x` 引入了 `narwhals` 依赖，而 `narwhals` 有 300 多个版本，pip 要拉一个很大的索引页来挑版本；国内镜像对这个页面的响应不稳定，连接挂住后不报错也不返回
- **解决**：在 `requirements.txt` 里显式约束 `altair>=5.0,<6`，装 5.x 就绕开了这条依赖链。绕开之后十几秒就装完
- **谁解决的**：A（2026-11-21）

> 顺带得出的教训：`requirements.txt` 里写 `>=` 是有害的。版本不固定时，pip 会装到最新版，
> 依赖链更长也更不稳定。改成 `==` 钉死版本后，装依赖变成确定性操作。

### 问题 2：Windows 上 pip 装完不退出，只能 Ctrl+C

- **现象**：终端已经打印 `Successfully installed ...`，但命令行提示符不回来，必须按 Ctrl+C 才能继续
- **原因**：包其实已经装好了。是 pip 进程在退出时被卡住，常见于 Windows Defender 实时扫描刚写入的几千个文件
- **解决**：看到 `Successfully installed` 就直接 Ctrl+C，不影响已装的包。用 `python -c "import xxx"` 验证即可确认装好了
- **谁解决的**：A（2026-11-21）

### 问题 3：预算表用 NULL 表示"总预算"，UNIQUE 约束失效

- **现象**：设计时想用 `category = NULL` 表示总预算，然后靠 `UNIQUE(month, category)` 防止同一个月重复设置
- **原因**：SQLite（以及标准 SQL）里 `NULL != NULL`，所以多行 `(2026-11, NULL)` 不会被唯一约束拦住，能重复插入
- **解决**：改用空字符串 `''` 表示总预算。已写进 `app/db/schema.sql` 的注释，并在本地用内存数据库实测验证过：`category=''` 时重复插入会正确抛出 `IntegrityError`
- **谁解决的**：A（2026-11-21）

> 这条答辩时值得主动讲——它体现的是"先验证再写文档"，而不是"照抄教程"。

### 问题 4：账单表为什么要有两个时间字段

- **现象**：一开始只设计了 `created_at`（入库时间），做完发现统计不对
- **原因**：用户今天补记昨天的账时，`occurred_at`（消费发生时间）是昨天，`created_at`（入库时间）是今天。只用一个字段，补记的账会算错月份
- **解决**：两个字段都要。**统计一律按 `occurred_at`，`created_at` 只用于排查**
- **谁解决的**：A（2026-11-21）

### 问题 6：示例数据每次跑都不一样，演示没法复现

- **现象**：第一版生成器每次运行都换一批数，截图上的"本月餐饮 115%"和现场跑到的不一致
  （有时 113%、有时 118%），评审问"你上次说的是 115% 还是这个？"就说不清
- **原因**：① 随机数没有固定种子；② "超支 115%"是靠随机金额累加出来的，天生不可控；
  ③ 本月餐饮的随机行还会和演示用的 3 笔混在一起，把比例冲掉
- **解决**：三件事
  1. 随机种子用 `anchor.toordinal()`（基准日的天序号）→ **同一天重复跑结果完全一样**，
     要固定就加 `--anchor 2026-11-22`
  2. "超支演示"那 3 笔写死：`328 + 296 + 296 = 920` 元，正好是餐饮预算 800 的 115%，不参与随机
  3. 随机生成的餐饮行一律挪到前两个月 → 本月餐饮只由那 3 笔构成，比例永远精确
- **谁解决的**：C（2026-11-22）
- **顺带**：日期用"相对基准日的偏移"而不是写死 `2026-11-01`。评审哪天 clone 我们不知道，
  写死日期过几个月数据全在"去年"，统计页空白、预算页没告警

### 问题 7：`--import` 不报错，但数据库里 0 条

- **现象**：在项目根目录跑 `python scripts/generate_sample_data.py --import`，
  打印"已生成 20 条"，但 `transactions` 表是空的，也没有任何报错
- **原因**：`python scripts/xxx.py` 时 `sys.path[0]` 是 `scripts/`，`import app` 失败；
  外层 `try/except Exception` 把 `ModuleNotFoundError` 吞了，静默降级成"只生成 CSV"
- **解决**：① 脚本开头加 `sys.path` 引导（和 `app/ui/main.py` 同一写法）；
  ② 失败时打印原因而不是静默；③ 导入前先 `init_db()`，空目录第一次跑也能建表
- **谁解决的**：C（2026-11-22）
- **教训**：**凡是"可选降级"的代码，必须把降级原因打出来**，否则等于把 bug 藏起来

### 问题 8：Key 还是占位符时，报错是 UnicodeEncodeError

- **现象**：`.env` 里按模板填了 `VLM_API_KEY=你的key`，调视觉模型时抛
  `UnicodeEncodeError: 'ascii' codec can't encode characters ... position 7-8`
- **原因**：占位符是中文；HTTP 请求头只能放 ASCII，openai SDK 构造 header 时直接编码失败。
  而 `config.vlm_ready()` 只判断"值非空"，占位符也算"已配置"
- **解决**：在 `app/ocr/receipt.py` 里加占位符检测（非 ASCII，或长度 < 16），提前抛人话：
  "视觉模型的 Key 还没填好……现在还是『你的key』这种占位符"
- **谁解决的**：C（2026-11-22）
- **教训**：**外部依赖（Key / 网络 / 额度）要在第 1-2 天用真实配置验一次**，不能等到做完了再调

### 问题 9：`st.dataframe` 一用整页就崩（numpy 的 DLL 被系统拦）

- **现象**：记账页用 `st.dataframe` 展示"本次会话已记的账"，页面直接报
  `ImportError: DLL load failed while importing _bounded_integers: 应用程序控制策略已阻止此文件`
- **原因**：这台机器的"应用控制策略"拦了 `numpy.random` 的 DLL；pandas 在 import 时会拉
  `numpy.random`，而 `st.dataframe` 内部要用 pandas。注意 `import numpy` 本身是好的，所以很容易误判
- **解决**：演示列表改成手写 Markdown 表格（零依赖）。另外提醒 A：统计页的 `st.altair_chart`
  也会经 pandas，动手前先跑 `python -c "import pandas"` 确认
- **谁解决的**：C（2026-11-22）
- **状态**：**未彻底解决**，目前只是绕开。后面要么关掉"智能应用控制"，要么在这个 venv 里重装 numpy / pandas

### 问题 11：外卖截图取了"总价"，没取"实付"

- **现象**：真外卖截图（老干妈火腿蛋炒饭）识别出 **15.90**，但图上印着"实付 **13.40**"。
  更麻烦的是 `confidence` 0.9、`missing_fields` 为空——系统不会拦，用户不仔细看就记错了
- **原因**：① prompt 只写了"只取合计金额"，外卖单上同时有"总价"和"实付"，模型挑了自己觉得像合计的那个；
  ② 把 prompt 改成"实付优先"之后**重跑仍然是 15.9**，说明这种字段选择靠 prompt 拧不稳
- **解决**：加规则兜底 `_fix_amount_with_text()`：从模型返回的 `raw_text` 里正则找
  "实付 / 支付金额 / 实收 / 订单金额"，找到就覆盖金额，并在备注写"已按『实付』金额记账"。
  实测 13.40 正确，4 张图回归全过（合成小票没有"实付"字样，不受影响）
- **谁解决的**：C（2026-11-23）
- **教训**：**"模型负责读，规则负责校正。"** 金额是纯数字，正则比模型可靠——和 `money.py` 是同一个思路

### 问题 12：模型置信度 1.0 也会判错

- **现象**：便利店小票（三明治 + 牛奶）被归到"购物"，预期是"餐饮"，`confidence` 仍是 **1.0**；
  外卖截图取错金额那次，`confidence` 也有 0.9
- **原因**：模型自评的 confidence 反映的是"它读得清不清"，不是"它判得对不对"。两者不是一回事
- **解决**：不把 confidence 当"正确性保证"，只当**门限**——低于 0.6 或 `missing_fields` 非空就强制人工确认；
  其余仍然走确认卡片，让用户能改
- **谁解决的**：C（2026-11-23）
- **答辩话术**：**"置信度只用来决定拦不拦，不用来保证对不对。"**

### 问题 13：Git Bash 里 `dir samples\receipts\real_01.jpg` 说文件不存在

- **谁解决的**：C（2026-11-23）

## 小提示

写的时候注意三点，答辩会追问：

1. **别只写"解决了"**。写清"为什么这么解决"，以及试过哪些没用的办法
2. **记上是谁解决的**。过程性评审看"实际贡献"，这份文档是证据之一
3. **失败的和放弃的也要记**。比如"试过用 Tesseract 识别中文小票，准确率撑不住，改用视觉模型"——这种比成功的记录更有说服力
